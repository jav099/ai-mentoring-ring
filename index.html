How to present
Undo, Compact, and Reset are in the top bar. The More menu contains Guide, Import, Export, and Working path. The context pane starts with only token usage, the editable limit, and the meter. Open Details for the breakdown, compaction comparison, Blocks and Text views, and selected block content. Clicking Inspect on a block also opens Details.
Click or drag a library block into the current agent's window. New blocks start collapsed and append to the end of their matching section, regardless of drop position. Agent setup uses related violet shades and appears above Conversation, which uses related blue shades. Icons, labels, and different tints distinguish the types. Drag existing blocks to rearrange them within their own section. Use the trash button to remove a block, or Undo to restore it. An empty Add creates a sample user message.
Use a normal block's chevron to expand its content for explanation, then collapse it again. The label and token count stay visible. This changes only the presentation: the full content still uses context. Saved display choices are preserved. A compacted conversation is different: its neutral grey summary capsule is locked and cannot be expanded, edited, excluded, or moved.
Vendor instructions always appear in a fixed grey block above history. They cannot be moved, edited, excluded, or removed. Their body can be collapsed, but their fixed header stays visible. They remain present across agent tabs, resets, and compaction, and count only once in the active input.
The optional context views show the next simulated model input for the selected agent, not every item visible in the history. Adding blocks or compacting does not open Details automatically. All example tasks, outputs, schemas, and summaries are synthetic.

      
Instructions, skills, and subagents

        
Instructions set scoped rules
Use them for stable coding conventions and constraints. Keep them focused. Do not put every optional workflow in an always-loaded file. A fresh conversation here contains only a small vendor scaffold. Add Host instructions, AGENTS.md, and Copilot instructions manually to show how each contributes to context. Adding one includes it for the current agent. Edit it to share it with all agents. Real products decide which files they discover and how conflicting guidance is handled; showing these files together does not mean every product loads both.

        
Skills supply a reusable workflow when needed
A skill normally has a name, description, a SKILL.md body, and optional resources. Use it for repeatable procedures. Keep trigger descriptions clear. Add Skill metadata from Agent setup to expose only its name, description, and file path. Add Invoke skill from Conversation to load the full SKILL.md body into context. Its card starts collapsed; expand it to show the file. These are separate steps. You can also show direct invocation without a discovery step. Referenced files are not loaded automatically. Compaction retains active setup metadata but can replace an invoked skill body with an automatic summary.

        
Subagents do bounded work in separate context
Use one for a task that benefits from isolation. Do not delegate a trivial step just to add an agent. Adding a subagent creates a child conversation with the delegated request. Its internal messages stay out of the parent input. Use Return summary to send selected findings back.

        
Read agent adds a small output snapshot
Add Read agent in the parent conversation to read the newest direct child's latest available Model output. Its default preview is limited to 480 characters, with a truncation notice when needed. The read has its own token cost and does not copy child setup or tool logs. If the child is compacted, only its visible summary is read. Existing read blocks are snapshots; add another read to fetch later output. A child without output returns a waiting status. With no child, the block uses a clearly labeled synthetic example. This is a bounded teaching model; real agent tools can return different amounts of history and cost more.

      

      
Where the files can live
These are documented examples, not a promise that every app or execution environment reads every location.

        
GitHub Copilot
Repository instructions: .github/copilot-instructions.md. Path-specific instructions: .github/instructions/*.instructions.md. Project skills can use .github/skills/<name>/SKILL.md; other supported locations depend on the surface. Custom agent definitions and runtime subagents are different concepts.

        
Claude Code
Project instructions use CLAUDE.md. Custom subagents can use .claude/agents/ or ~/.claude/agents/. What each subagent inherits depends on its type and configuration.

        
Codex
Repository instructions use AGENTS.md. Local skills can use .agents/skills/<name>/SKILL.md or ~/.agents/skills/. Supported scopes and discovery behavior are product-specific.

      
To create or edit a customization, change the relevant file in its intended scope, use the product's supported metadata, and test that it loads for the intended task. Reload behavior differs between products.

      
Path-specific instructions
Add Scoped AGENTS.md or Scoped Copilot, then open More and set Working path to src/ui/Button.tsx. The directory instructions and matching applyTo rules enter the next input. Move to src/api/routes.ts to compare the context. Edit a scoped block to change its directory or pattern. This demo supports * and ** globs and comma-separated patterns.
Scoped AGENTS.md represents a file under a directory, such as src/ui/AGENTS.md. Scoped Copilot represents .github/instructions/ui.instructions.md with applyTo frontmatter. Repository-wide .github/copilot-instructions.md is not the path-specific file format.
The live path filter is an educational simplification, not a universal reload rule. Copilot applies matching path-specific instructions on supported surfaces. Codex builds its AGENTS.md chain at run or session startup. A real agent can retain previously read instructions in conversation history; changing directories does not necessarily remove them. Here, the filter deliberately shows the instructions relevant to the selected next input.

      
Tools and MCP servers
A tool definition tells an agent what it can call. A call contains arguments. A result returns data. An MCP server can expose tools or resources; connecting it does not load its entire data set into the model.
The GitHub MCP fixture exposes 24 substantial synthetic tool definitions. Its eager catalog costs more context than several skill invocations. These are representative examples, not exact GitHub MCP signatures or universal sizes. Small servers can be much lighter. Real products may defer tool definitions instead of loading the whole catalog. You add calls and results separately; external results are data, not system instructions.

      
Protect the context window
The model has a finite input budget. Large tool results, repeated text, instructions, skill bodies, and conversation history can use that space. A repository existing on disk does not mean all its files are in the prompt.
Compact replaces all conversation blocks for the current agent with one grey, locked summary capsule. The summary is automatic and deliberately lossy. Original blocks are hidden and excluded from the next model input. They cannot be expanded or edited through the capsule. Undo restores the original conversation so you can compare which requirements or evidence were lost.
Setup remains colored in its own section and is not compacted. Matching scoped instructions, metadata, and exposed schemas stay available, so compaction does not remove an expensive eager tool catalog. The token total, percentage, and meter show the current input. The percentage can exceed 100% when the input is over budget. A short result below the meter shows the last compaction's savings and unchanged setup cost. Details contains the section breakdown and exact before/after totals. That comparison is a snapshot of the operation; live totals still follow the currently selected agent and path. A large setup can keep the meter nearly full even after the conversation becomes a short summary.
New messages appear after the locked capsule. Compact again merges them into one capsule rather than accumulating summaries. You can remove the capsule without revealing old blocks or deleting child-agent conversations.
Counts are computed from the full represented text, including collapsed schemas, at one estimated token per four characters. The fixtures model representative relative costs, not measured product traces. The default 16,000-token teaching budget is adjustable and is not a vendor model limit. Message envelopes, output reserves, caching, real tokenization, and product-specific trimming are omitted.
